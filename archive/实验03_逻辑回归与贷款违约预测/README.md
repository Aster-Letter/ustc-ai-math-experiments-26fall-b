## 最短运行路线

沿用课程环境，在 `code/` 中执行：

```bash
conda activate ustc-ai-experiments-26fall-B
python checkpoints.py C0
```

按顺序补 `student.py`，每完成一个阶段运行 `python checkpoints.py C1` 等对应命令。全部完成后：

```bash
python checkpoints.py all
python run_lab.py
# 查看验证结果，记录选定方案；主实验阈值预先固定为 0.5。
python run_lab.py --final-test
```

缺少依赖时，在已激活环境运行 `python -m pip install -r requirements.txt`；已可运行的环境无需重装。无需下载数据或配置加速硬件。

## 数据来源与范围

从用户提供的天池 80 万条带标签训练数据中，固定抽取 **8000/1000/1000** 条。按指导书将训练集改为正负各 **4000 条**；验证、测试保留上一版的相同记录，各含 200 条违约。先用种子 20261008 重建原划分，再用种子 20261009 补充训练正类并打乱，三份编号互斥。保留原编号与 47 列，模型只选八个输入字段；这不是教材原有的抽样。全部标签有效，输入中仍有真实缺失值。

平衡抽样改变训练类别比例，模型输出不能直接解释为自然人群的已校准违约概率。参考运行召回率由 6% 升至 59%，精确率由 80% 降至约 32%；这是在已查看过的相同测试集上做的教学对照，不是新的盲测。训练两类数量相同，常数基线预先约定总预测未违约。

`testA.csv` 没有真实标签；`sample_submit.csv` 的 0.5 是提交示例。两者不能替代课堂测试标签。默认结果写入 `code/outputs-tianchi-balanced/`，与旧模拟结果分开；测试集在 `--final-test` 时读取。旧模拟材料保留在教师归档，学生包只包含真实数据课堂子集。

## 实验报告与提交

参照实验 01 的提交方式，提交 `学号_姓名_lab03.zip`，内含代码、运行所需数据和 **`report.pdf`**。报告首页写实验名称、学号和姓名，正文按四部分组织：

1. **实验概况与完成总览**：概述任务，列出 C0–C7 的完成状态和已知问题。
2. **分阶段实现与验证**：每个 checkpoint 写“实现思路与关键代码—小例子输入及预期/实际输出—结果解释”。注明对应文件、函数；通常摘录约 3–10 行关键代码即可，不贴整个文件。C0 记录运行和修改观察；C6 保留一次参数更新的简短手算及代码对照。
3. **综合实验结果**：数据来源及清洗前后样本数、运行设置、三方案验证对比、一张选定方案的训练/验证损失曲线、最终测试指标与混淆矩阵。矩阵注明行是真实类别、列是预测类别，0=未违约、1=违约。
4. **结果分析与总结**：结合实际输出分析损失变化、误报与漏判、验证阈值变化和数据局限，简述收获或建议。

从[报告模板](report-template.md)填写并导出 `report.pdf`，无需再提交 Markdown 模板。各检查点的具体记录要求已放入模板和实验手册第 7 节；只贴 `PASS` 不能代替实现说明和数值验证。综合图表集中放在第 3 部分，各检查点可引用，不重复贴图。不要求安装证明、整篇理论推导或完整日志。报告数值必须来自本次提交的代码，未完成项如实说明。
