## 1. 提交前需要完成什么

- 补全 `operator_exercises.py` 和 `student_encoder.py`，完成卷积、激活、池化与编码器自检。
- 运行基础编码器与一个改进编码器，使用提供的同一解码器，保持数据划分、分辨率、种子和训练预算一致，记录主要改动。
- 根据验证集选择最终模型，再运行完整真实测试集评估。不要根据测试分数反复选模型或调整阈值。
- 根据 `report-template.md` 写报告，导出为 `report.pdf`。包括层尺寸与参数表、训练曲线、对照结果、至少3个成功和3个失败样例及原因分析。
- U-Net 为选做，自行编写；学生包不提供它的代码骨架。选做者一并提交新增源码、检查结果、对照记录与理论分析。

这里的 IoU（Intersection over Union，交并比）与 Dice 均为逐图前景指标再取平均。统一使用128×128评估网格和0.5概率阈值，忽略原始标注值3。不把合成图、限量调试分数或课件中的教师结果作为本人实验成绩。

## 3. README.md 应写清什么

请写入姓名学号、Python与PyTorch版本、运行设备、各模型对应的107作业编号、最终选中哪组及理由、数据来源和放置位置、各实验的完整命令，以及新增或修改了哪些文件。未完成项与借助的资料或工具也应如实记录。

从提交目录根部可按下面的命令复核保存的最终模型。把 `--data-dir` 换成评估机器上包含 `splits.json` 与 `oxford-iiit-pet/` 的目录；在107平台应通过分配了计算资源的作业执行，不要在登录节点直接跑完整评估。

```bash
python selected/source/evaluate.py \
  --checkpoint selected/best.pt \
  --data-dir /实际数据路径/data \
  --device cuda --split test --output verify-test-01
```

`verify-test-01` 是新建的复核输出目录，不能与已有输出重名。复核用于确认保存与恢复一致，不用于重新挑选模型。原始 `run.json` 中的训练路径保留原样，在 README 中补充新机器的路径映射即可。

- 完整宠物图片集、标注归档、下载缓存；保留小型的 `splits.json` 即可。
- Conda环境、虚拟环境、安装包、`.git/`、`__pycache__/`、`.pyc`、`.DS_Store`。
- 教师讲义、课堂PPT、课程材料压缩包、教师参考代码与教师模型权重。
- 所有历史权重或重复备份；最终权重与对应代码必须保留。

不要修改程序生成的指标、训练记录或日志来掩盖失败。若正式运行未完成，应在报告中说明，保留已有记录。
