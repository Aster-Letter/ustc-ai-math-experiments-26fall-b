# 任务一：微型书店数据管理与统计

> 阅读本说明，在 [book_tasks.py](book_tasks.py) 中完成 `LAB01_TODO B1–B6`，通过[独立验证](check_book_tasks.py)检查，再使用菜单运行完整程序。环境安装见[实验手册](../../实验01_实验手册.md)。

## 项目简介

一家小书店保存着图书的进货成本、当前售价、库存，以及已经发生的销售记录。本项目中，你将补全一个小型数据管理程序：查询预算内有货的图书，补充库存、修改售价并保存，再统计每种书的销量、销售额和毛利。

图书信息和销售记录分别保存在两份 CSV 文件中。CSV（Comma-Separated Values，逗号分隔值）是一种用纯文本保存表格数据的格式：每行是一条记录，同一行的各列用英文逗号分隔。本项目的 CSV 第一行是表头，写出各列的名称；后续每行才是实际数据。下面会把文件中的文本与对应表格放在一起，方便对照阅读。

程序的菜单、文件读写公共流程和结果显示已提供。你主要实现图书对象、查询与更新、销售记录的解析，以及两步销售计算。相同的读取流程通过继承复用，不需要为两个 CSV 分别写一套打开文件和逐行读取的代码。

### 两份数据怎样关联

`books.csv` 的一行表示一种书，书名在书库中唯一：

```csv
title,cost,price,stock
动手学深度学习,20,32,5
Dive into deep learning,20,32,3
简·爱,15,25,4
pixiv 2025插画年鉴:VISIONS,10,18,0
```

上面的 CSV 文本对应下表，表头中的英文名称与文件字段一一对应：

| 书名（`title`） | 进货成本（元/册，`cost`） | 当前售价（元/册，`price`） | 库存（册，`stock`） |
| --- | ---: | ---: | ---: |
| 动手学深度学习 | 20 | 32 | 5 |
| Dive into deep learning | 20 | 32 | 3 |
| 简·爱 | 15 | 25 | 4 |
| pixiv 2025插画年鉴:VISIONS | 10 | 18 | 0 |

`cost` 是每册进货成本，`price` 是当前售价，`stock` 是当前库存。同名书的进货成本在本项目中保持不变。

如需测试，可以考虑直接修改 `books.csv`，但应保留表头和字段类型，书名保持唯一。程序运行时会检查导入的 CSV 是否符合要求——不符合格式的文件会抛出异常，详见 `book_support.py` 中的实现。

`sales.csv` 的每一行是一条销售记录，同一本书可以出现多次：

```csv
title,quantity,unit_price
动手学深度学习,2,30
pixiv 2025插画年鉴:VISIONS,3,18
动手学深度学习,1,32
简·爱,2,25
```

对应的表格如下；同名书的不同销售记录分别占一行：

| 书名（`title`） | 销售数量（册，`quantity`） | 成交单价（元/册，`unit_price`） |
| --- | ---: | ---: |
| 动手学深度学习 | 2 | 30 |
| pixiv 2025插画年鉴:VISIONS | 3 | 18 |
| 动手学深度学习 | 1 | 32 |
| 简·爱 | 2 | 25 |

销售额使用记录中的 `unit_price`，毛利计算还需要通过书名查询书库中的 `cost`。当前售价改变，不应改变过去的销售额。当前库存为零的书仍然可能有历史销售，读取记录时也不再次扣库存。

## 实现步骤

### B1：建立图书对象

补全 `Book.__init__(title, cost, price, stock)`，把参数保存为 `self.title`、`self.cost`、`self.price` 和 `self.stock`。传入的金额和册数已经转换成数值，无需在这里读取文件。

不同对象保存各自的数据。改变一本书的价格或库存，不应影响另一本书。

### B2：修改对象状态

补全两个小方法：

- `restock(quantity)`：将当前库存增加 `quantity` 册。
- `set_price(price)`：把当前售价改为新的 `price`，保留进货成本和库存。

菜单已检查输入是否合法。这两个方法负责改变对象，不需要打开或写入 CSV。修改后选择菜单中的“保存书库”，公共工具才将当前对象写入文件。

### B3：复用读取流程，解析销售记录

先阅读已完成的 `BookReader.parse_row`。它取得一行字符串字段，转换金额和库存，最后创建 `Book` 对象。

`BookReader` 和 `SalesReader` 都继承 `CSVReader`。父类的 `read(path)` 负责打开文件、读取表头并遍历各行；处理每一行时调用 `self.parse_row(row)`。因此，执行 `SalesReader().read(path)` 时，实际使用的是你在销售读取器中补全的转换方法。

请补全 `SalesReader.parse_row(row)`，返回一个字典：

| 字段 | 返回类型 | 内容 |
| --- | --- | --- |
| `title` | 字符串 | 去除两端空白的书名 |
| `quantity` | 整数 | 销售册数 |
| `unit_price` | 浮点数 | 实际成交单价 |

例如输入 `{"title": " 动手学深度学习 ", "quantity": "2", "unit_price": "30"}`，应得到 `{"title": "动手学深度学习", "quantity": 2, "unit_price": 30.0}`。

无需重写 `read`，也不需要复制文件打开与循环代码。公共框架负责导入格式问题的提示，不要求为每个函数重复增加异常处理。

### B4：查询预算内有货的图书

补全 `affordable_books(catalog, budget)`。`catalog` 是以书名为键、以 `Book` 对象为值的字典。

返回库存大于零、且当前售价不超过 `budget` 的书名列表，保持书库原有顺序。预算是单本书的价格上限；没有符合项时返回空列表。默认数据在预算 30 元时，结果是 `['简·爱']`。

这里使用图书对象的当前售价；不要用历史销售记录的成交价判断现在可以买哪些书。

### B5：关联记录并整理数组

补全 `prepare_sales(catalog, records)`。这是销售统计的第一步：逐条取出书名、销量和成交价，通过书名查找成本，然后整理成以下字典：

| 键 | 内容与类型 |
| --- | --- |
| `titles` | 每条销售记录的书名列表 |
| `quantities` | 同一顺序下的销量，一维整数 NumPy 数组 |
| `unit_prices` | 同一顺序下的成交单价，一维浮点 NumPy 数组 |
| `costs` | 按书名查到的进货单价，一维浮点 NumPy 数组 |

四列的位置一一对应。默认销售记录应得到数量 `[2, 3, 1, 2]`、成交价 `[30, 18, 32, 25]`、成本 `[20, 10, 20, 15]`。同名销售记录仍分别保留，不能被字典中后一次赋值覆盖。

先收集列表，再用 `np.array(..., dtype=int)` 或 `dtype=float` 转换即可。输入保证书名能够在书库中找到；不要修改书库或销售记录。没有销售记录时，返回空书名列表和三个空的一维数组。

### B6：计算销售额和毛利

补全 `calculate_sales(quantities, unit_prices, costs)`。这是第二步：使用整理好的数组，完成四个变量的计算，返回字典的代码已提供。

- `line_revenue`：每条记录的销售额，即销售册数乘成交单价。
- `line_profit`：每条记录的毛利，即销售册数乘“成交单价减进货单价”。
- `total_revenue`：所有销售额之和。
- `total_profit`：所有毛利之和。

NumPy 数组的乘法可以逐元素计算，`np.sum` 可以求和。输入数组可能为空，此时总额应为零。毛利也可能为负，不要把低于成本的成交金额强行改为零。

按书名汇总销量与显示表格的代码已提供，表格列出销售记录中出现的书名。默认数据的结果为：

| 图书 | 销量（册） | 销售额（元） | 毛利（元） |
| --- | ---: | ---: | ---: |
| 动手学深度学习 | 3 | 92 | 32 |
| pixiv 2025插画年鉴:VISIONS | 3 | 54 | 24 |
| 简·爱 | 2 | 50 | 20 |
| 合计 | 8 | 196 | 76 |

这里的毛利只扣除了图书进货成本，没有计入租金等其他费用。

## 使用菜单与保存

完成 B1 后即可启动菜单，尚未完成的功能会提示对应 TODO：

```bash
python book_tasks.py
```

菜单提供查看书库和库存统计、按书名查询、预算筛选、补货、改价、保存、销售统计。可以先补货、再查看库存，或改价后重新执行预算查询，观察对象状态如何影响结果。

“保存书库”默认写入同目录的 `books_updated.csv`，保留原始 `books.csv`。覆盖已存在的输出文件前会询问确认；有未保存修改时退出，程序会询问保存、放弃还是继续操作。

重新加载保存后的数据时执行：

```bash
python book_tasks.py --books books_updated.csv
```

默认输入从脚本目录寻找；手动传入的相对路径从终端当前目录寻找，因此上述命令应在 `code/bookstore` 目录运行。也可以用 `--sales` 指定销售文件、用 `--output` 指定另一个保存路径。

你可以直接编辑 CSV 来尝试其他数据，但应保留表头和字段类型，书库中的书名保持唯一，销售记录中的书名应在书库中存在。初始导入失败会明确抛错，程序不会悄悄替换成默认书库。
